# Playwright Automation Test Framework

A TypeScript UI automation framework for [Automation Exercise](https://automationexercise.com) using Playwright, Cucumber.js, Gherkin, and the Page Object Model (POM). It includes a Cucumber BDD suite, sequential Chromium/Edge runs with comparison reports, and a standalone Playwright Test smoke test.

## What is included

- Gherkin feature files for homepage title validation and end-to-end user registration.
- Cucumber step definitions written in TypeScript.
- Page objects and locator models that keep browser interactions out of step definitions.
- Per-scenario browser setup and teardown through Cucumber hooks.
- Sequential Playwright Chromium, Microsoft Edge, or both-browser Cucumber execution in headed or headless mode.
- Normalized Cucumber results and aggregate Chromium/Edge comparisons.
- Timestamped HTML reports for individual browser runs and browser comparisons.
- Failure screenshots attached to Cucumber steps, preserved in normalized results, and displayed in reports.
- A Playwright Test smoke test with HTML reporting, screenshots, and traces on failure.
- Strict TypeScript compiler settings for the test and framework source.

## Architecture

### Cucumber execution flow

```text
Feature file → Cucumber tag selection → step definitions
    → page object → locator model → Playwright browser
    → raw Cucumber JSON → normalized results → HTML report
```

`src/support/hooks.ts` launches a browser before each scenario, creates the browser context and page objects, and closes all resources afterward. The default `chrome` option launches Playwright's bundled Chromium; `--browser=edge` launches the installed Microsoft Edge channel. The `HEADLESS` environment variable controls headed/headless mode and defaults to headless when it is not set. An `AfterStep` hook captures a full-page screenshot for failed steps when a page is available. `src/support/world.ts` exposes the browser and page objects to step definitions through the custom Cucumber World.

When `--browser=all` is used, the runner executes Chromium and then Edge sequentially. Each browser writes its own raw Cucumber JSON, normalized JSON, and HTML report under the same execution directory. The normalizer retains status, duration, error details, and screenshot attachments. The comparison matches features by URI, scenarios by identity, steps by keyword/name/line, and hooks by type and occurrence; it then generates aggregate JSON and HTML reports with status and matched-scenario duration summaries. A comparison is only generated when both browsers have normalized results.

The runner accepts `--grid=<url>` and checks the Grid `/status` endpoint before starting the suite. This is currently an availability check only: the hooks launch local browsers and do not connect Playwright sessions to Selenium Grid.

Page objects represent the user-facing areas used by the current registration flow:

- `HomePage`: navigation, title validation, links, and logged-in username.
- `LoginSignup`: signup form text, fields, and buttons.
- `Signup`: account details, radio buttons, dropdowns, checkboxes, and account creation.
- `AccountCreated`: account-created/deleted messages and the Continue link.

The accompanying `models/` classes centralize locators used by these page objects.

### Playwright Test execution flow

`tests/smoke.spec.ts` uses `playwright.config.ts`. It runs against the configured base URL, `https://automationexercise.com`, in headless Chromium and verifies that the homepage title contains “Automation Exercise”. It is separate from the Cucumber runner and does not use its browser, headless, tag, or Grid options.

The Playwright Test configuration enables:

- Parallel execution.
- Two retries and two workers in CI.
- An HTML report that is not opened automatically.
- Traces retained on failure.
- Screenshots captured only on failure.
- 10-second action and 30-second navigation timeouts.

## Prerequisites

- Node.js and npm.
- Git.
- Internet access for npm packages, the Chromium browser binary, and the Automation Exercise site.
- Microsoft Edge installed locally when using `--browser=edge` or `--browser=all`.
- A reachable Selenium Grid `/status` endpoint when using `--grid`.
- VS Code is recommended, but not required.

Use a current Node.js LTS release where possible. The project is currently developed with Node.js 24.21.0.

## Installation

Clone the repository and install the locked dependency versions:

```powershell
git clone https://github.com/SairamPabbisetty/Playwright-Automation-Test-Framework.git
cd Playwright-Automation-Test-Framework
npm ci
npx playwright install chromium
```

The equivalent project setup script performs both installation steps:

```powershell
npm run setup
```

`npm ci` uses `package-lock.json`; do not use `npm install` when a reproducible installation from the lockfile is required.

## Running tests

### Run the default Cucumber registration scenario

```powershell
npm test
```

The `test` script runs:

```text
node scripts/run-cucumber.js --tag=@RegisterUser --headless=false --browser=all --grid=http://localhost:4444
```

This checks that Selenium Grid is available at `http://localhost:4444`, then runs the `@RegisterUser` scenario in headed mode first in Playwright Chromium and then in Microsoft Edge. Both browsers run locally; the Grid is not used to host browser sessions. The scenario creates a user with the data in `features/ui/RegisterUser.feature`, verifies the account, and deletes the account at the end.

### Run Cucumber with a different tag, browser, or execution mode

The runner accepts `--tag`, `--headless`, `--browser`, and `--grid` options. Supported browser values are `chrome` (Playwright Chromium), `edge`, and `all`:

```powershell
node scripts/run-cucumber.js --tag="@SmokeTest" --headless=true
node scripts/run-cucumber.js --tag="@HomePage" --headless=false
node scripts/run-cucumber.js --tag="@SmokeTest" --browser=edge --headless=true
node scripts/run-cucumber.js --tag="@RegisterUser" --browser=all --headless=true
node scripts/run-cucumber.js --tag="@SmokeTest" --browser=chrome --headless=true --grid=http://localhost:4444
```

Playwright Chromium is the default browser. Use `--headless=true` or `--headless=false` explicitly; the Cucumber hooks default to headless mode when `HEADLESS` is not set. `--grid` accepts an `http` or `https` URL, validates the Grid status, and aborts if the Grid is unavailable. It does not enable remote browser execution.

Available tags in the current feature files are:

- `@RegisterUser`: complete registration, account verification, and account deletion flow.
- `@SmokeTest`: homepage title validation.
- `@HomePage`: homepage title validation.

To run all Cucumber scenarios, omit `--tag`:

```powershell
node scripts/run-cucumber.js --headless=true
```

### Run the Playwright Test smoke suite

```powershell
npx playwright test
```

The standalone Playwright Test suite always runs headless Chromium against `https://automationexercise.com`; its settings are independent of the Cucumber runner's browser, headless, tag, and Grid options.

Useful Playwright Test commands:

```powershell
npx playwright test tests/smoke.spec.ts
npx playwright test --headed
npx playwright show-report
```

## Cucumber and browser comparison reports

Every runner invocation creates a unique execution directory using the local date, time, and a short unique ID:

```text
reports/
└── Nov2026/
    └── 13-11-2026-17-19-31-a1b2c3d4/
        ├── chrome/
        │   ├── cucumber-report.json
        │   ├── normalized-results.json
        │   └── report.html
        ├── edge/
        │   ├── cucumber-report.json
        │   ├── normalized-results.json
        │   └── report.html
        └── comparison/
            ├── comparison-results.json
            └── comparison-report.html
```

The execution path format is `reports/<MonYYYY>/<DD-MM-YYYY-HH-mm-ss>-<8-character-id>/`. Single-browser runs have a folder for the selected browser; the `comparison/` folder is created for multi-browser runs.

Each browser's `report.html` includes scenario and step statuses, durations, totals, failure details, and embedded screenshots when available. For `--browser=all`, `comparison-results.json` contains aggregate feature, scenario, step, hook, functional-status, and matched-scenario performance data. `comparison-report.html` presents the comparison details, error information, and screenshots when available; it can be printed or saved as PDF. Reports open automatically when configured; if they do not, open the HTML files from the execution directory manually.

Comparison can also be run manually after normalized results for both browsers are available:

```powershell
node scripts/compare-browser-results.js ".\reports\Nov2026\<execution-id>"
node scripts/generate-browser-comparison-report.js ".\reports\Nov2026\<execution-id>"
```

The first command writes `comparison/comparison-results.json`; the second creates `comparison/comparison-report.html`.

To inspect generated reports from PowerShell:

```powershell
tree /F reports
```

## TypeScript validation

Run the TypeScript compiler without emitting JavaScript:

```powershell
npx tsc --noEmit
```

The compiler includes `src/**/*.ts`, `tests/**/*.ts`, and `features/**/*.ts` and uses strict type checking as configured in `tsconfig.json`.

## Configuration reference

| File | Responsibility |
| --- | --- |
| `package.json` | Dependency manifest and `setup`/`test` npm scripts; the default test runs registration on both browsers |
| `config/report.config.js` | Central report paths and report-generation/opening options |
| `cucumber.js` | Cucumber feature paths, TypeScript loading, hooks, step definitions, timeout, and JSON output |
| `scripts/run-cucumber.js` | Tag, browser, headless, and Grid validation; sequential runs; report generation; and browser comparison orchestration |
| `scripts/normalize-cucumber-results.js` | Converts raw Cucumber JSON into browser-specific normalized results |
| `scripts/compare-browser-results.js` | Matches Chromium and Edge features, scenarios, steps, and hooks and writes aggregate comparison JSON |
| `scripts/generate-cucumber-report.js` | Converts Cucumber JSON into a browser-specific HTML report |
| `scripts/generate-browser-comparison-report.js` | Creates the aggregate browser comparison HTML report |
| `playwright.config.ts` | Playwright Test discovery, browser, URL, retries, workers, timeouts, and reporters |
| `tsconfig.json` | Strict TypeScript compiler settings and included source paths |

### Report options

The centralized report configuration reads these environment variables. All options default to `true`:

| Variable | Effect |
| --- | --- |
| `REPORT_CUCUMBER_JSON` | Generate raw Cucumber JSON (required for normalized JSON or HTML generation) |
| `REPORT_NORMALIZED_JSON` | Generate normalized per-browser JSON |
| `REPORT_HTML` | Generate per-browser Cucumber HTML reports |
| `REPORT_OPEN_HTML` | Open generated HTML reports automatically on Windows |

Set a variable to `false` to disable that output, for example in PowerShell:

```powershell
$env:REPORT_OPEN_HTML = "false"
node scripts/run-cucumber.js --tag="@SmokeTest" --browser=all --headless=true
```

The runner rejects report settings that request normalized JSON or HTML while raw Cucumber JSON is disabled. Browser comparison requires normalized results for both browsers.

## Adding coverage

To add a Cucumber scenario:

1. Add or update a `.feature` file under `features/`.
2. Add matching step definitions under `src/step-definitions/`.
3. Add or extend a page object under `src/pages/`.
4. Keep selectors in the corresponding model under `src/models/`.
5. Run the tagged scenario and `npx tsc --noEmit`.

For an independent Playwright Test, add a `.spec.ts` file under `tests/` and use the fixtures and configuration provided by `@playwright/test`.

## Current scope

The framework currently covers:

- Homepage title validation.
- User registration with account information and preferences.
- Logged-in username verification.
- Account deletion.
- A standalone homepage smoke test.
- Local Playwright Chromium and Microsoft Edge execution for Cucumber scenarios.
- Sequential two-browser comparison with JSON and HTML reports.
- Failed-step screenshot capture and report display when screenshots are available.
- Optional Selenium Grid availability validation before a Cucumber run.

Remote browser execution through Selenium Grid, API testing, CI/CD workflows, additional page objects, and expanded test data management are not currently implemented.
